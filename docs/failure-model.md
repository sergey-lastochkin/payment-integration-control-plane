# Сценарии сбоев

Сохранённый актуальный локальный прогон: [summary.json](../failure_lab/runs/local-2026-08-11-01/summary.json). Каждая строка создана `failure_lab/run.py`, а не заполнена вручную; предыдущий run остаётся в репозитории как исторический артефакт.

| Сбой | Поведение модели | Граница доказательства |
|---|---|---|
| Повторное создание или HTTP-запрос | Повторно используется одна операция | Локальный SQLite и file adapter |
| Ответ отправителя потерян после принятия | Операция не переоткрывается; пришедший статус сохраняет `accepted` | Локальный адаптер возвращает статус до TimeoutError |
| Повторный status callback после reopen | SQLite inbox возвращает сохранённое решение | Локальная модель обработки статуса |
| Повторная выписка после reopen | SQLite ledger помечает строку replay | Локальный matcher |
| Та же event/statement identity с другим payload | Конфликт, `manual_check`, без молчаливого принятия | Локальный SQLite ledger |
| Равные кандидаты | `manual_check`, без автоматического выбора | Локальный matcher |
| Потерянный ответ после send | После restart становится `outcome_unknown`; нужен status lookup, reconciliation или manual resolution | Controlled fault injection |
| Два независимых worker | Один successful claim и один локальный send attempt | `multiprocessing` + SQLite |
| Повреждённый конверт | SHA-256 не совпадает, конверт отклоняется | Локальный файловый адаптер |
| Ручное решение | Terminal status с источником `manual_resolution` | Локальная модель аудита |

Тест не подтверждает поведение конкретного банка. Для тестового банка требуется отдельная карта ошибок: какие ответы гарантируют отсутствие приёма, а какие оставляют исход неопределённым.
